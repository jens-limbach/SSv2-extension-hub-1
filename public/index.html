👋 Introduction

Below you find seven extension use cases to demonstrate the most common extension use cases. Each of them leverages a different “cloud function” of our microservice. Each of them will be used to demonstrate how we can extend our SAP Sales and Service Cloud with logic that is running side-by-side in another microservice. We linked at the bottom some additional helpful resources like documentations, blogs, githubs and videos. If you look for a general introduction into extensibility we highly recommend you this overview video.

⚙️ One-Time Setup: Communication System

Before you can connect any of the endpoints below, you need to register this microservice once in SAP Sales and Service Cloud V2. All later steps then simply reuse this communication system and only require the endpoint's path.

  1. In SSC V2, navigate to System Settings → Communication Systems.
  2. Create a new communication system.
  3. Provide a name, description and open the Outbound tab, click the create button and set the host to this service's host name (shown below but remove the https when you copy).
  4. Set the authorization method to None.
  5. Save and activate the communication system.

In-memory & demo-only: resets on restart, affects one instance, and is not persisted. Credentials are sent to the microservice over the current connection and are never stored server-side or echoed back (the values you type stay only in these form fields). Credentials of the microservice itself are securely stored in environment variables on the backend.

🛰️ APIs

The use cases above are all cases where SAP Sales and Service Cloud V2 calls into this microservice. This final section flips the direction and shows one deliberately-chosen example of calling an SSC V2 REST API outbound — the Signals API, which posts an external highlight for an account so it appears in that account's 360 view. We keep it to this one example on purpose: the full REST API catalogue, including Swagger examples, is already covered in the official API documentation.

📜 Viewing Logs

You most likely deployed this app with the Cloud Foundry CLI (cf push). To watch what the microservice is doing — including the emoji-prefixed operational output — you only need one more command: 

# Live tail of the logs
cf logs crm-extension-hub

# Dump the most recent logs and exit
cf logs crm-extension-hub --recent

Replace crm-extension-hub with your app name from manifest.yml if you changed it. Log lines use ✅ info · 🔄 async started · ⏳ waiting · 📡 outbound call · ⚠️ warning · ❌ error.
