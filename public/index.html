👋 Introduction

Below you find five example endpoints. Each of them is a “cloud function” of our microservice. Each of them will be used to demonstrate how we can extend our SAP Sales and Service Cloud with logic that is running side-by-side in another microservice.

⚙️ One-Time Setup: Communication System

Before you can connect any of the endpoints below, you need to register this microservice once in SAP Sales and Service Cloud V2. All later steps then simply reuse this communication system and only require the endpoint's path.

  1. In SSC V2, navigate to System Settings → Communication Systems.
  2. Create a new communication system.
  3. Provide a name, description and open the Outbound tab, click the create button and set the host to this service's host name (shown below but remove the https when you copy).
  4. Set the authorization method to None.
  5. Save and activate the communication system.

📜 Viewing Logs

You most likely deployed this app with the Cloud Foundry CLI (cf push). To watch what the microservice is doing — including the emoji-prefixed operational output — you only need one more command: 

# Live tail of the logs
cf logs crm-extension-hub

# Dump the most recent logs and exit
cf logs crm-extension-hub --recent

Replace crm-extension-hub with your app name from manifest.yml if you changed it. Log lines use ✅ info · 🔄 async started · ⏳ waiting · 📡 outbound call · ⚠️ warning · ❌ error.
